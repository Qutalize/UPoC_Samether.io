**バージョン**: 1.0 / **作成日**: 2026-07-12

## 1. プロジェクト背景と目的

### 1.1 背景

調布市には郷土博物館・深大寺をはじめとする歴史資源が豊富に存在するが、若年層の認知度・来訪率は高くない。既存のリアルタイム位置情報連動ゲーム「サメザリオ」（Go WebSocket + Phaser 3、AWS運用実績あり）の技術基盤を流用し、「遊びながら調布の歴史スポットを実際に巡る」体験を提供する。

### 1.2 目的

| # | 目的 | 測定指標（KPI案） |
|---|---|---|
| 1 | 調布市の歴史・名所（郷土博物館等）の認知度向上 | エリア解放数 / ユーザー、スポット詳細閲覧数 |
| 2 | 指定スポットへの実来訪による地域回遊性の向上 | 写真照合成功数（＝現地訪問数） |
| 3 | SNS拡散による普及 | シェア実行数、シェア経由の新規流入 |

### 1.3 位置づけ

- 調布市UEC U☆PoCコンテスト（テーマ①：地域の歴史発信）プロトタイプ審査（8/28）向け
- **8月中旬に機能完成**、以降は現地テスト・発表準備のバッファとする

## 2. ターゲットユーザー

| 区分 | ペルソナ | 想定行動 |
|---|---|---|
| プライマリ | 調布市内・近隣の学生（UEC生含む）、10〜20代のスマホゲームユーザー | 通学・散歩ついでにスポットを訪れエリアを解放、SNSでシェア |
| セカンダリ | 京王線沿線の子育てファミリー | 週末に子どもとスタンプラリー感覚で巡る |
| ターシャリ | 郷土博物館・市の観光担当者 | 来訪促進ツールとして活用、審査・展示での利用 |

利用環境: スマートフォンのモバイルブラウザ（iOS Safari / Android Chrome）。アプリインストール不要のWebアプリ（既存PWA構成を継承）。

## 3. システム構成

**方針: 既存AWS構成を最大限流用し、新規リソースは最小限（S3バケット1つ程度）に抑える。**

```
[モバイルブラウザ]
  Phaser 3 + TypeScript + MapLibre GL JS（既存流用）
  ├─ WebSocket (wss)  … ゲームプレイ・進捗同期（既存 /ws 拡張）
  └─ HTTPS            … 写真アップロード・照合API（★新規 /api/verify）
        │
     [ALB]（既存）
        │
  [ECS Fargate: Go Server]（既存）
  ├─ WebSocket Hub / GameLoop 20tick/s（既存）
  ├─ Botロジック（既存・パラメータ調整のみ）
  ├─ ★ステージ管理（ステージ別ルーム or エリアマスク）
  ├─ ★画像照合サービス（perceptual hash比較）
  └─ ★ユーザー進捗管理（解放ステージ・ポイント）
        │
  [ElastiCache Redis]（既存）
  ├─ リーダーボード ZSET（既存）
  └─ ★ユーザー進捗 HASH（unlocked_stages, points）
        │
  [Amazon Location Service]（既存）
  ├─ Maps: ステージ選択マップ・赤ピン表示（既存Map流用）
  └─ Tracker: 歩行距離CP（既存機能そのまま）

  [S3 + CloudFront]（既存）… フロント配信
  [S3]（★新規 or 既存バケットにprefix追加）… 照合用リファレンス画像・投稿写真の一時保管
```

## 4. 機能要件

### 4.1 機能一覧表

| ID | 機能名 | 概要 | 優先度 | 新規/流用 |

| F-01 | ログイン/セッション | プレイヤー名によるセッション管理 | 必須 | 流用 |
| F-02 | ステージ選択マップ | 調布市マップ上に7〜8ステージを表示。解放済み＝カラー、未解放＝グレー/雲マスク。にゃんこ大戦争風の進行導線 | 必須 | 新規 |
| F-03 | ステージ制ゲームプレイ | 選択したステージのエリア内でサメザリオ本編をプレイ。未解放ステージは選択不可 | 必須 | 変更 |
| F-04 | 初期エリア制限 | 初期状態では調布駅エリアのみ、かつ駅中心の狭い範囲のみプレイ可能 | 必須 | 変更 |
| F-05 | 写真照合によるエリア解放 | 指定スポット（郷土博物館等）で指定アングルの写真を撮影・アップロード→照合成功でエリア全体解放 | 必須 | 新規 |
| F-06 | 位置チェック | 照合時に `getCurrentPosition` で現在地を取得し、スポットから半径150m以内であることを検証（なりすまし防止の第2要素） | 必須 | 新規 |
| F-07 | 赤ピン演出 | 照合成功の瞬間、マップ上に該当エリアの歴史スポットの赤ピンがドロップ&バウンドのアニメーションで出現 | 必須 | 新規 |
| F-08 | 歴史スポット情報表示 | ピンタップでスポットの説明（郷土博物館提供の解説文・写真）を表示 | 高 | 新規 |
| F-09 | SNSシェア | 照合に使った写真＋ハッシュタグ付きテキストをX等でシェア（Web Share API / Xインテント） | 高 | 新規 |
| F-10 | シェアボーナス | シェア実行でゲーム内+100ポイント付与（1スポット1回まで） | 高 | 新規 |

| F-12 | ラスボスステージ | 最終ステージ「深大寺エリア」。全ステージ解放後に挑戦可能。強力なBotボス（例: メガロドン）配置 | 高 | 変更 |
| F-13 | 進捗永続化 | 解放ステージ・ポイントをサーバー側(Redis)に保存し、デバイスをまたいで復元 | 必須 | 新規 |
| F-14 | 歩行距離CP | 既存の歩行計測→CP機能はそのまま維持 | 中 | 流用 |
| F-15 | リーダーボード | ステージごと or 全体のスコアランキング | 中 | 流用 |

### 4.3 主要ユースケースフロー

**UC-1: エリア解放**
1. ユーザーがステージマップで未解放エリアをタップ → 解放条件（スポット名・指定アングルのサンプル写真・地図）を表示
2. 現地に移動し「写真を撮って解放」をタップ → カメラ起動（`<input type="file" capture="environment">`）
3. 撮影 → 位置情報取得 → `POST /api/verify` に写真+ステージID+座標を送信
4. サーバーが (a)ジオフェンス判定 (b)pHash照合 を実施 → 成功なら進捗更新し結果返却
5. クライアントで解放演出（エリアマスク消滅 + 赤ピンドロップアニメーション + 効果音）
6. 「この写真をシェアして+100pt」ボタン表示 → シェア実行でボーナス付与

## 5. 非機能要件

| 分類 | 要件 |
|---|---|
| 性能 | ゲーム同期は既存同等（20tick/s、同時50人/ルーム）。照合APIは応答3秒以内（pHash計算は数十ms想定） |
| 可用性 | ハッカソン審査期間中の稼働を最優先。既存のECS単一タスク構成で可（冗長化は不要） |
| セキュリティ | 画像アップロードはサイズ上限5MB・MIMEチェック。照合の位置情報検証はサーバー側で実施。既存のCORS/セキュリティヘッダを継承 |
| 不正対策 | (1)ジオフェンス必須 (2)pHashしきい値照合 (3)同一ユーザーの連続照合試行に対するレートリミット（例: 30秒に1回）。※完全な不正防止は審査版ではスコープ外と明記 |
| プライバシー | 投稿写真は照合後に削除 or 7日で自動削除（S3ライフサイクル）。位置情報は照合判定のみに使用しトラッキング保存しない旨をガイドに明記 |
| コスト | 新規AWSコストはS3数円/月程度。Rekognition等の従量課金サービスは使わない（pHashはサーバー内計算） |
| 対応環境 | iOS Safari 16+ / Android Chrome 最新。**GPS常時トラッキングには依存しない**（iOS制約対応。位置取得は照合時の単発 `getCurrentPosition` のみ） |
| 保守性 | ステージ・スポット定義はコードから分離したJSON（`stages.json`）とし、博物館フィードバックによる差し替えを容易にする |
| 工数制約 | メンバー3〜4名・8月中旬まで多忙。既存コード改修範囲を最小化し、新規はステージ管理・照合API・マップUIの3点に集中 |
